# Hard 진행 기록과 회사 순위 설계

## 목표

Hard 스테이지를 끝까지 클리어하지 못해도 도달한 라운드가 개인 기록과 회사 순위에 남도록 한다. 기존 Hard 회사 순위 화면을 진행 순위로 전환하고, 기존 완주 시간 기록은 보존한다.

## 확정된 결정

- 진행 기록은 스테이지별 최고 도달 라운드와 최근 도달 라운드로 저장한다.
- 스테이지의 라운드에 진입하면 도달로 인정하고 자동 저장한다. 스테이지 첫 진입은 1라운드 도달이다.
- 순위 우선순위는 라운드 높은 순, 클리어 우선, 사망 적은 순, 시간 빠른 순이다.
- 기존 Hard 회사 순위를 별도 보드로 복제하지 않고 최고 도달 순위로 전환한다.
- 기존 개인 완주 시간 기록은 그대로 유지한다.
- 기존 완주 순위 항목은 8라운드 클리어로 해석해 새 순위에서도 보존한다.
- 저장 형식과 API의 구버전 호환을 함께 처리한다.

## 기록과 순위 규칙

스테이지별 Hard 진행 기록은 `best`와 `recent`를 가진다. 각 값은 다음 필드로 구성한다.

```text
{
  roundReached: 1..8,
  cleared: boolean,
  elapsedTicks: non-negative integer,
  deaths: non-negative integer
}
```

`roundReached`는 해당 시도에서 실제로 진입한 가장 높은 라운드다. 라운드 진입 순간의 누적 `elapsedTicks`와 `deaths`를 해당 도달 기록에 저장한다. 최종 스테이지 클리어 시 `cleared`를 `true`로 바꾸고 8라운드 진행 기록을 확정한다. 사망은 Hard 시도를 끝내지 않으며, 이후 더 높은 라운드에 진입하면 그 시점의 누적 사망 수와 시간을 기록한다.

`recent`는 가장 최근 시도의 현재 최고 도달 라운드를 나타낸다. 새 시도를 시작하면 1라운드로 시작하고, 이후 더 높은 라운드에 진입할 때마다 최근 기록을 갱신한다. `best`는 진행 기록 비교 규칙을 만족하는 결과로만 교체한다. 따라서 같은 라운드에 다시 도달한 시도는 사망 수와 도달 시간으로 기존 최고 기록과 비교된다.

`best`는 아래 순서로 더 나은 결과를 선택한다.

1. `roundReached`가 더 큰 결과
2. 같은 라운드에서는 `cleared: true`인 결과
3. 같은 라운드와 클리어 여부에서는 `deaths`가 더 작은 결과
4. 앞 조건이 같으면 `elapsedTicks`가 더 작은 결과

회사 순위도 같은 순서를 사용한다. 모든 정렬 기준이 같으면 표시 이름, 사용자 ID 순으로 안정적으로 표시한다. 동점 순위 계산에서는 표시 이름과 사용자 ID를 순위 기준에 포함하지 않는다.

## 개인 기록 화면

- Hard 개인 기록에 최고 진행과 최근 진행을 표시한다.
- 각 진행에는 도달 라운드, 클리어 여부, 사망 횟수, 경과 시간을 표시한다.
- 기존 `최고 기록`과 `최근 기록` 완주 시간 카드는 기존 값을 그대로 표시한다. 진행 기록을 완주 기록에 덮어쓰지 않는다.
- 기존 스테이지 선택, 모바일 내 기록/회사 순위 탭, 창 스크롤 동작을 유지한다.

## 회사 순위 화면

- 기존 `hard:<stageId>` 보드 ID를 유지해 기존 회사 순위를 최고 도달 순위로 전환한다.
- Hard 순위 행은 순위, 플레이어, 도달 라운드, 클리어 여부, 사망 횟수, 경과 시간을 보여준다.
- 상위 10명과 10위 밖의 본인 순위를 표시하는 기존 동작을 유지한다.
- 기존 Easy 라운드별 순위 형식과 순서는 변경하지 않는다.
- 저장 순위(stale), 오프라인, 불러오기 실패 및 재시도 표시는 현재 동작을 유지한다.

## 저장 및 기존 데이터 호환

- 로컬 저장 형식을 v7에서 v8로 올리고, Hard 진행 기록을 스테이지별 `best`와 `recent`로 추가한다.
- 기존 로컬 저장은 개인 완주 기록을 유지하면서, 완주 기록의 `best`와 `recent`를 각각 8라운드 클리어 진행 기록으로 변환한다. 완주 이력이 없는 스테이지의 진행 기록은 비워 둔다.
- 클라우드 저장 형식을 v8로 올린다. API와 클라이언트는 기존 v6/v7과 새 v8을 읽고, 저장 시 v8로 정규화한다. 이는 현재 클라이언트의 v7 payload와 API의 v6 검증 형식 간 차이도 함께 수용한다. API 병합은 Hard `best`에 위 순위 비교 규칙을 적용하고, `recent`는 가장 최근 시도의 입력으로 갱신한다.
- 새 클라이언트가 기존 버전의 클라우드 저장을 읽어도 Easy 진행, 개인 완주 기록, 진행 중인 run을 잃지 않아야 한다.
- 기존 Hard 회사 순위 문서에 진행 필드가 없으면 해당 행을 `roundReached: 8`, `cleared: true`로 정규화하고 기존 시간과 사망 수를 보존한다. 별도의 대량 재작성은 요구하지 않는다.
- 기존 사용자 진행 기록을 새 보드에 올릴 때는 새 저장 데이터에서 Hard 진행 후보를 갱신한다. 새 진행이 기존 완료 기록보다 순위가 낮으면 기존 8라운드 클리어 행을 덮어쓰지 않는다.

## 자동 저장 시점

- Hard run을 처음 바인딩할 때 현재 라운드 진행을 기록한다.
- 이후 각 라운드 진입 때 진행 기록을 갱신하고 즉시 저장을 요청한다.
- 기존 사망, 라운드 완료, 주기적 스냅샷, 페이지 이탈 시 저장 경로와 연결해 최근 진행을 보존한다.
- 오프라인이나 인증 문제에서는 기존 로컬 저장 동작을 유지한다. 동기화에 실패해도 로컬 진행 기록을 지우지 않는다.

## 범위 밖

- Easy 개인 기록 또는 Easy 회사 순위의 산정 규칙 변경
- 완주 시간 기록 제거 또는 재정의
- 새로운 Hard 순위 보드 추가
- 회사 순위 상위 10명 및 본인 순위 표시 방식 변경

## 완료 조건

- Hard 스테이지를 클리어하지 않아도 진입한 최고 라운드가 로컬과 클라우드 진행 기록에 저장된다.
- 클리어 전 기록도 기존 Hard 회사 보드에서 조회되고, 지정한 정렬 우선순위가 정확히 적용된다.
- 이전 Hard 회사 순위 항목은 8라운드 클리어로 보존된다.
- 기존 개인 완주 시간 기록과 Easy 기록, 진행 중인 run이 저장 마이그레이션 후에도 보존된다.
- 개인 기록 화면에 최고/최근 진행이 보이고 기존 완주 시간 기록도 계속 보인다.
- 저장 버전이 다른 클라이언트/API 사이에서도 저장을 읽고 병합할 수 있으며 진행 정보를 조용히 버리지 않는다.
