# Plan: 보스 공격 및 등장 에셋 재구성

## Goal
숲·기계·벌레 보스의 기본 외형·색감·게임상 크기를 유지하면서 공격 자세와 본체 밖 공격을 실제 스프라이트로 연결한다. 숲 뿌리는 팔 접지 후 1페이즈 60틱, 2페이즈 30틱·60틱에 발생하고 사전 바닥 예고를 없앤다. 기계 처치 후 벌레는 240틱 동안 맵 깜빡임 → 실루엣 돌출과 포효 → 전체 암전 → 완전한 외형 공개 순서로 등장한다.

## Task Sequence
1. T01: 실제 PNG 원화와 패킹·등록·공통 스프라이트 표시 계약. 본체 24프레임 구조는 유지하고 외부 효과는 별도 시트로 분리한다.
2. T02: 숲 보스의 가지팔·내려찍기·독립 뿌리 표시와 접지 기준 시간. 뿌리 표시 수명을 저장·복구할 수 있게 한다.
3. T03: 공유 렌더러를 사용하는 기계·벌레 공격을 함께 연결한다. 보스 소유 hazard에만 새 표시를 적용한다.
4. T04: 4초 벌레 등장·포효 타이밍·연습 시작점·복구를 연결하고 전체 자동 검증을 수행한다.

## Why One Phase
모두 동일한 로컬 게임의 에셋·렌더링·시뮬레이션 연결 작업이다. 외부 서비스 배포나 별도 승인 마일스톤이 없어 Phase를 나누지 않는다. 실제 파일이 없는 텍스처를 먼저 등록하면 자산 검사와 로딩이 깨지므로 T01에서 원화·출력·등록을 함께 완성한다. 광산 두 보스는 `MineHazardView.js`를 공유하므로 T03에서 함께 처리한다.

## Measurable Completion
- 참조 원화에 기반한 본체 공격 프레임 3종과 독립 효과 시트 4종이 실제 PNG로 존재하며, 패킹을 반복해도 같은 출력이 나온다.
- 가지·꼬리의 본체 연결, 피해 핵심 형상의 영역 일치, 회복 상태에서의 두 번째 뿌리 표시를 자동 검증한다.
- 뿌리 접지·발생과 벌레 등장 단계 경계가 60Hz 시뮬레이션 틱으로 검증된다.
- 이전 저장에 새 표시 필드가 없어도 복구 가능하며, 등장 중 저장·일시정지·연습 시작이 같은 상태를 재현한다.
- `npm.cmd test`, `npm.cmd run build`가 통과한다. 구현 단계에서 실제 PNG와 연락 시트를 파일로 관찰한다. 사람의 조작감·실제 청취 확인 여부는 별도로 기록한다.

## Scope and Working Rules
- 지금은 계획만 작성한다. 생성·편집되는 문서는 `.memory/` 안에만 둔다. 실행·원화 제작·프로덕션 코드 수정은 후속 `/memory-execute` 요청에서 시작한다.
- 플레이어 피격 자세·밀림·무적 깜박임과 전용 피격 효과는 현행 유지다. 일반 적, 광차, 회복물약, 체력, 피해량, RNG·공격 선택은 이번 새 표현의 대상이 아니다.
- 모든 공격을 투사체로 통일하지 않는다. 기존 히트박스와 hazard가 유일한 피해 근거다. 별도 표시 타이머로 피해를 발생시키지 않는다.
- 공격 시간 예외는 숲 뿌리의 새 접지 기준 및 벌레 등장 180→240틱이다. 기존 2페이즈 전환의 30틱 암전·포효는 별개다.
- 사용자가 직접 플레이 대신 로직 확인을 요청했다. 에이전트 브라우저 조작·자동 플레이는 검증 요구에 넣지 않는다. 이미지 파일 확인과 자동 로직 검증을 사용하고, 사람의 체감 검증을 했다고 주장하지 않는다.
- 작업 전부터 수정돼 있던 `.memory/current.md`, 이전 T03·phase.md와 새 결정 문서를 보존한다. 이전 가시성 T04를 임의로 완료 처리하거나 커밋하지 않는다. 현재 포인터의 원본은 날짜가 붙은 archive 문서로 보존한다.
- 전체 계획을 한 번에 커밋하지 않는다. 실행 시 Task별 자산 패킹·집중 검사·빌드 후 해당 Task의 Commit Message로 커밋하고 진행 상태를 갱신한다.

## Adjacent Matters Reported Separately
- 코드상 벌레 잠복 준비 중에도 본체 접촉 피해는 남아 있다. 이번에는 접촉 가능한 본체를 완전히 감추지 않는 표시 기준을 적용하며 판정은 유지한다. 완전한 잠복과 접촉 피해 제거까지 포함할지는 별도 사용자 선택 사항으로 보고한다.
- 이전 가시성 계획 T04가 아직 `in_progress`이고 현재 사용자는 기존 화면·소리를 정상이라고 보고했다. 과거 인수를 새 작업 완료로 간주하지 않으며 이전 기록은 남긴다.
- 기존 빌드 기록에 약 1.46MB 번들 경고가 있다. 번들 분할·최적화는 새 Task로 추가하지 않았다. 포함 여부는 별도 사용자 선택 사항이다.
- 관리자 인증 기반 라운드 선택은 별도 서버 권한 작업이다. 개발용 선택기의 `mine-worm` 시간 상수만 이번 등장과 일치시킨다.
