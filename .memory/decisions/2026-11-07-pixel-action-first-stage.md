# Decisions: Pixel Action 첫 스테이지

- Date: 2026-11-07
- Status: Confirmed
- 인터뷰 범위: 독립 게임의 첫 버전을 설계한다. 이 문서는 구현 계획이나 코드가 아니다.

## D01. 프로젝트 관계와 작업 위치
- **Chosen**: 기존 Knight Run과 저장·장비·랭킹을 공유하지 않는 별도 게임이다. `C:/DuringDex/dev_games/pixel-action`을 독립 프로젝트 폴더로 사용하고 별도 Git 저장소로 관리한다.
- **Chosen**: 작업명은 `Pixel Action`이며 정식 제목은 플레이해본 뒤 결정한다. PC 웹 브라우저에서 로컬 서버를 통해 실행한다.
- **Rationale**: 사용자가 새 콘셉트와 별도 프로젝트를 선택했다. 기존 게임과 미푸시 로컬 커밋은 보존하며, 코드·설계는 필요한 부분만 참고한다.

## D02. 장르와 세계관
- **Chosen**: 옆에서 보는 횡스크롤 플랫폼 액션. 저주받은 숲·폐허를 배경으로 한 고딕 잔혹 동화 분위기다. 무거운 설정 속에서도 캐릭터와 공간은 동화처럼 표현한다.
- **Chosen**: 주인공은 낡은 망토와 간결한 검을 든 떠돌이 검사다. 기존 기마 기사·적·배경 외형을 유지하는 요구는 이 새 게임에 적용하지 않는다.
- **Rationale**: 사용자가 게임 콘셉트 자체를 변경했고 새 게임에 맞는 인물과 환경을 선택했다.

## D03. 도트 시각 방향
- **Chosen**: 작은 도트의 픽셀 크기를 통일하되 캐릭터와 적의 가로·세로 픽셀 수는 대상에 맞게 자유롭게 정한다. 정확히 16×16 픽셀로 제한하지 않는다.
- **Chosen**: 단순한 형태와 제한된 색, 선명한 실루엣을 사용한다. 화면에서 주인공은 작게 보이고 숲과 지형을 넓게 보여준다. 배경·발판·이펙트·UI도 도트 감성으로 통일한다.
- **Chosen**: 이미지 생성과 후처리를 활용해 주인공·적·보스·배경 등 도트 소재를 새로 제작한다. 인접 프레임의 형태와 색, 픽셀 격자, 기준점이 일관되고 실제 게임에서 읽히는지를 확인한다.
- **Rationale**: 작은 도트라도 기기 화면상 확대 배율과 캐릭터 픽셀 수는 다른 개념이며, 명확한 실루엣이 게임 플레이에 필요하다.

## D04. 조작 및 이동
- **Chosen**: PC 키보드·마우스 우선. `A`/`D`로 좌우 이동, `Space`로 점프, 마우스 왼쪽 클릭으로 일반 공격, `Shift`로 구르기, `E`로 공중 내려베기를 사용한다. 방향키·모바일·게임패드 지원은 첫 버전 요구가 아니다.
- **Chosen**: 점프는 버튼을 누르는 길이에 따라 높이가 달라지고 공중 추가 점프는 없다. 조작과 이동은 빠르고 명확하되 적 공격을 보고 피할 수 있는 속도로 조정한다.
- **Rationale**: 사용자가 빠른 플랫폼 액션과 구체적인 키 배치를 지정했다.

## D05. 일반 공격과 조준
- **Chosen**: 마우스 포인터 방향으로 360도 근접 공격한다. 클릭을 이어 누르면 최대 3타가 연결되고, 마우스를 누른 채 유지해도 자동 연속 공격하지 않는다. 콤보가 진행되는 동안 첫 공격 방향을 유지한다.
- **Chosen**: 캐릭터 몸은 공격 방향의 8방향 도트 동작으로 표현하고 검은 마우스 포인터의 자유 각도를 따른다. 몸의 방향 표현과 실제 공격 범위가 서로 어긋나지 않도록 검증한다.
- **Rationale**: 사용자가 자유 조준과 방향에 맞는 캐릭터 동작, 콤보 중 방향 고정을 선택했다.

## D06. 공중 내려베기와 구르기
- **Chosen**: 공중에서 `E`를 누르면 수직 급강하하여 바닥에 착지하면서 아래쪽 적을 한 번 공격한다. 착지 후 짧은 재사용 대기시간이 있다. 공중 일반 공격은 좌클릭이며 내려베기와 구분한다.
- **Chosen**: 구르기는 별도 `Shift` 입력이며 동작 전체가 무적이다. 구르기 종료 후 짧은 재사용 대기시간을 둔다.
- **Rationale**: 사용자가 처음의 자동 공중 내려베기를 별도 스킬로 변경하고 명시적인 조작을 지정했다.

## D07. 체력·피해·회복
- **Chosen**: 체력은 하트 3칸. 일반 적 접촉, 적 공격, 보스 공격의 피해는 각각 1칸이며 적과 몸이 닿아도 피해를 받는다. 피격 직후에는 짧은 무적 시간을 둔다. 발판 사이 구덩이에 떨어지면 남은 체력과 관계없이 즉시 쓰러진다.
- **Chosen**: 스테이지의 회복 아이템은 닿으면 자동으로 하트 1칸을 회복한다. 체력이 가득 차 있어도 아이템은 소비된다. 체크포인트에서 부활하면 체력을 회복한다.
- **Rationale**: 일관된 한 칸 피해와 회복량으로 체력을 직관적으로 읽을 수 있게 한다.

## D08. 스테이지와 적
- **Chosen**: 첫 버전은 2~5분을 목표로 하는 저주받은 숲 스테이지 하나를 완성한다. 낮은 발판과 구덩이를 넘는 가벼운 플랫폼 구간과 단순한 진행 경로를 둔다.
- **Chosen**: 일반 적 3종은 근접 검을 쓰는 나무 병사, 원거리 마법을 쓰는 숲의 망령, 예고 후 돌진하는 멧돼지다. 공격 예고와 회피·반격 기회를 알아볼 수 있어야 한다.
- **Chosen**: 보스는 가지와 뿌리로 공격하는 거대하고 무게감 있는 타락한 고목 수호자다. 체력이 절반 이하가 되면 새 공격과 더 빠른 패턴이 나타나는 2단계 전투다. 보스 이름과 체력을 화면 상단의 전용 바로 표시한다. 보스전 시작 후 승리 또는 플레이어 사망까지 구역을 잠근다.
- **Rationale**: 사용자가 서로 다른 전투 역할의 적과 단계 변화가 있는 숲의 수호자를 선택했다.

## D09. 체크포인트와 하드 모드
- **Chosen**: 일반 모드의 첫 스테이지 중간에 체크포인트 1개를 둔다. 사망하면 마지막 체크포인트에서 체력을 회복해 부활하고 모든 적이 다시 나타난다. 이미 소비한 회복 아이템은 다시 나타나지 않는다.
- **Chosen**: 첫 버전은 일반 모드만 제공한다. 추후 하드 모드는 처음부터 선택 가능하며, 사망 시 스테이지 시작 지점으로 돌아가고 적 체력·공격력과 공격 패턴이 강화된다. 보상은 기록과 칭호로 하며 캐릭터 능력치는 영구 성장하지 않는다.
- **Rationale**: 사용자는 하드 모드 규칙을 정한 뒤 구현을 추후로 명시적으로 연기했다.

## D10. 성장·기록·저장
- **Chosen**: 장비 강화나 영구 능력치 성장 없이 플레이어의 실력으로 도전한다. 첫 버전은 수집물 없이 클리어 시간과 사망 횟수를 표시한다.
- **Chosen**: 이 브라우저에 자동 저장 슬롯 하나를 사용한다. 마지막 체크포인트에서 게임을 이어가고 최고·최근 클리어 기록을 각각 보관한다. 최고 기록은 최단 시간이며 해당 도전의 사망 횟수를 함께 표시한다.
- **Chosen**: 기록 시간은 스테이지 도전 전체에 걸쳐 사망 후 재도전 시간도 누적한다. 일시정지와 게임을 종료한 동안의 시간은 제외한다. 온라인 랭킹은 나중에 결정한다.
- **Rationale**: 기존 게임과 독립된 실력 중심의 로컬 기록을 선택했다.

## D11. 애니메이션·카메라·사운드
- **Chosen**: 플레이어의 대기·이동·점프·공격·구르기·피격·쓰러짐과 적의 이동·공격·피격·쓰러짐을 제작한다. 풍부한 대기 동작과 보스 등장·단계 전환 연출도 포함한다.
- **Chosen**: 카메라는 이동 방향을 조금 더 보여주며 주인공을 부드럽게 따라간다. 배경음과 효과음을 모두 포함한다. 효과음은 직접 제작하고 배경음은 사용 조건이 명확한 음원을 활용한다.
- **Rationale**: 사용자가 기본 동작을 넘어 보스와 분위기 연출까지 포함하도록 선택했다.

## D12. 화면 흐름과 설정
- **Chosen**: 타이틀 화면에서 시작·이어하기·기록·설정을 제공한다. 첫 스테이지는 스토리 설명 없이 시작하며, 별도 인게임 튜토리얼을 띄우지 않는다. 조작법은 타이틀 화면의 설정이나 조작 설명에서 확인한다.
- **Chosen**: `Esc` 일시정지 메뉴에서 재개·설정·처음 화면으로 이동할 수 있다. 설정에는 배경음·효과음 음량, 전체화면, 화면 흔들림 조절을 제공한다.
- **Rationale**: 사용자가 빠른 게임 진입과 필요한 설정을 메뉴에서 확인하는 흐름을 선택했다.

## 구현 계획에서 정할 세부 수치
- 실제 도트 시트 크기와 방향·애니메이션 프레임 수, 공격 범위, 쿨다운, 무적 시간, 점프 높이와 속도, 적 체력, 보스별 패턴 및 배치, 체크포인트 위치와 회복 아이템 개수는 게임을 플레이하며 구체화한다. 선택하지 않은 수치를 사용자 결정으로 취급하지 않는다.
- 첫 버전의 상태 모델은 체크포인트 복귀, 사망 횟수, 누적 플레이 시간 및 이미 소비한 회복 아이템을 새로고침·재실행 후에도 일관되게 다룰 수 있도록 설계한다.

## 기존 프로젝트에서 확인한 점과 별도 범위
- 기존 `knight-run`은 Phaser/Vite를 사용하며, 수평 이동·접촉 피해와 해당 규칙을 서버에서 재현하는 랭킹/PvP 구조가 있다. 새 점프·자유 방향 공격에 기존 전투 시뮬레이터를 그대로 적용할 수 없다. 엔진·도구는 재사용할 수 있고 계정·저장·서버는 새 요구를 정한 뒤 선별한다.
- 기존 로컬 `main`은 인터뷰 당시 원격보다 24개 커밋 앞서 있었다. 새 폴더 작업과 무관하게 기존 폴더 및 로컬 Git 이력을 보존한다. 푸시나 배포는 이 인터뷰에서 수행하지 않는다.
- 기존 게임의 강화 파괴 장비 복구, 실제 서버/SQL 검증 및 미적용 PvP migration은 기존 프로젝트의 별도 후속 항목이다. 새 게임의 이번 범위에 포함하지 않는다.

## D13. 로컬 저장 백업 — 사용자 선택
- **Chosen**: 브라우저 데이터 삭제 시 진행·기록이 사라질 수 있다는 점을 인지하고 수동 백업·복구 기능은 첫 버전에서 제외한다. 추후 포함 여부를 결정한다.
- **Rationale**: 사용자가 자동 저장 한 칸을 유지하며 별도 백업 기능을 이후로 미루기로 선택했다.
